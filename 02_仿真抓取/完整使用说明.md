## 启动

打开桌面 **RoboBrain → 02_仿真抓取**，双击 **RoboBrain 仿真抓取 Demo**。固定使用 `twin_env` 启动仿真，并以独立的 `brain_env` 子进程加载本地 RoboBrain2.5-4B；不需要手动切换 Conda。主框架代码位于本目录的 `demo/`，RoboTwin 只提供环境和机器人 API。

```bash
bash /root/Desktop/RoboBrain/02_仿真抓取/run_brain_twin_demo.sh
```

当前容器有桌面显示（`DISPLAY`）时，上面的命令默认打开交互式 SAPIEN Viewer；窗口会显示机器人、桌面、玩具车和篮子的实时物理运动。Viewer 目标刷新约 25 FPS，传感器图像读取限制为 15 FPS；RoboBrain 加载和 MPlib 规划等待期间仍持续处理窗口拖动、旋转和缩放。

显式选择模式：

```bash
# 强制打开 Viewer，并在任务完成后保持窗口，按回车关闭
bash /root/Desktop/RoboBrain/02_仿真抓取/run_brain_twin_demo.sh --keep-viewer

# 无图形窗口运行，适合 SSH 或后台任务
bash /root/Desktop/RoboBrain/02_仿真抓取/run_brain_twin_demo.sh --headless
```

没有显示器的服务器需要先配置 X11/VNC/远程桌面并设置 `DISPLAY`，否则使用 `--headless`。

不录制视频时追加 `--no-video`。直接运行原入口也可：

```bash
/opt/conda/envs/twin_env/bin/python -u /root/Desktop/RoboBrain/02_仿真抓取/demo/brain_twin_pipeline.py
```

原入口在有 `DISPLAY` 时同样默认打开 Viewer；用 `--headless` 可关闭。

## 本次实现

1. SAPIEN 建立真实物理场景：ALOHA-AgileX、玩具车、篮子与桌面，固定 seed=0。
2. 相机拍摄场景，交给 `brain_env` 中的 RoboBrain；保存实际模型回答。
3. 验证模型返回的 `pick_and_place` / `toycar_to_basket` 指令；无效指令报错，不执行替代动作。
4. MPlib 规划抓取；通过关节驱动和物理步进闭合夹爪。
5. 进入预先捕获的搬运姿态，按当前物体与夹爪偏移计算篮子上方目标。
6. 松爪，让玩具车依重力落入篮子；读取实际物体位置与接触状态。
7. 同一机械臂抓篮子并抬升，调用原任务 `place_object_basket.check_success()`。
8. 保存阶段画面、录像、日志和报告；失败返回非零退出码。

## 修复要点与范围

早期临时测试提前创建了全部 Action，导致所谓“向上移动 10 cm”实际上是在初始姿态上方搬运。正式脚本在抓取后才创建 Action，产生了不同姿态。现在明确保存初始末端姿态作为搬运目标，统一测试与正式执行流程；同时保留已验证的规划顺序和同臂抓篮子流程。

本演示使用真实 SAPIEN 刚体碰撞、夹爪接触和关节轨迹，没有执行中传送物体、固定物体到夹爪或修改成功条件。MPlib 原有回退可能将不可达目标沿 z 轴调整，实际执行的偏移会记录在报告中。

RoboBrain 负责在受约束提示下选择高层技能，具体抓取位姿和物体位置使用 RoboTwin 的仿真真值与抓取标注，底层由预编写技能和 MPlib 执行。它是高层大脑与技能执行器的最小演示，尚未实现纯视觉 6D 定位、端到端 VLA、网络分布式服务或持续逐步大脑重规划。两个 Conda 环境通过进程和 JSON 分离，后续可替换成 ROS 2 服务。

仅使用已准备的最小机器人/篮子/玩具车资产；启动不会下载完整资产包。当前验证范围是 seed=0 的固定场景，不代表随机场景的成功率。
